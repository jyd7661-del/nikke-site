> 근거: `docs/log/2026-09.md`의 "AI 조합 실험 1·2차", "얇은 로스터 × 판정 결과", "얇은 로스터 재현(씨앗 2)".
> 이 문서는 **아직 코드가 아니다.** 아래 "유저 결정" 3가지가 정해지면 순서대로 구현한다.

## 0. 실측이 말해 준 것 (설계의 전제)

> 2026-09-15 추가: 홈 목록에 SR이 들어와 **초보 로스터(SSR 4~8 + SR)**가 실제 입력이 된다. 이 구간은 폴백이 100% 열리므로 AI 전환의 효과가 가장 큰 자리다. 얇은 로스터 eval에 씨앗 3(초보 유형)을 추가할 것.

## 1. 구조 — 혼합(hybrid), 엔진은 검산기로 남는다

```
요청(보유 로스터 · 모드 · 보스/타워 · lang)
  │
  ├─ 엔진: findRealUsageTeamMatch / findExactTeamMatch  ──열리면──▶ 그대로 사용(지금과 동일, AI는 설명만)
  │
  └─ 둘 다 null(폴백 구간 = 얇은 로스터의 60~90%)
        │
        ├─ 캐시 조회: sha256(정렬된 보유 id + 모드 + 보스 + 타워 + 프롬프트 버전)  ──적중──▶ 반환
        │
        ├─ AI 호출(소넷, temperature 0, 구조화 출력: members[5] + reasoning)
        │     └─ 검산(엔진 규칙): 5명 유효 · 로스터 안 · 버스트 1/2/3 성립 · 타워 입장 · 미지 이름 0
        │            위반 → 1회 재요청(위반 사유를 붙여서) → 또 위반이면 엔진 폴백(지금 답)으로
        │
        └─ 저장 후 반환. 응답에 `model: 'ai-composed'`를 넣어 화면에서 출처를 밝힌다
```

- **왜 폴백만 바꾸는가:** AI가 이긴 40건은 전부 폴백 구간이었다. 실사용 완전일치는 "사람들이 실제로 클리어에 쓴 조합"이라
  AI가 이길 이유가 없고, 이기더라도 판정할 방법이 없다. 처음부터 전부 바꾸면 검증 가능한 부분까지 잃는다.
- **검산기가 곧 안전망:** 지금 `verify` 19종은 엔진이 결정적이라 성립한다. AI 구간은 결정적이지 않으니 검사가 아니라 **평가(eval)**로 바꾼다(§5).

## 2. 프롬프트 v3 (실험 프롬프트 `scripts/aiTeamPrompt.mjs` + 두 가지)

| 블록 | 내용 | 등급 |
|---|---|---|
| 규칙 | 지금 그대로(버스트 커버, 버프 범위, 타워 입장, 보스 약점 문구) | — |
| 로스터 | **보유 캐릭터만**(SSR+SR — 2026-09-15부터 홈 목록에 SR 20명, R 제외) 한 줄씩: title·class·burst·element·weapon·manufacturer·overspec·squad·skills[3] 원문 + `usage{tier,pct}` | A |
| **시너지 짝(신규)** | `synergyNotes.synergyPairs`(13) + `archetypes`(483) 중 **멤버가 전부 로스터 안에 있는 것만** — 이름·멤버·이유(lang) | A (prydwen/enikk 원문) |

| 출력 | JSON: `members[5]`, `roles{title: 'B1'|'B2'|'B3'}`, `reasoning`(lang, 2~3문장), `warnings[]`(예: "약점 속성 딜러 없음") | — |

- 게이지 속도 표는 **넣지 않는다.** `data/`에 출처 있는 값이 없다(weapons.json은 연사속도뿐, B등급). 넣으려면 먼저 1차 출처를 찾아 데이터에 넣고 검사를 붙인다.
- 프롬프트 버전 문자열(`v3`)을 캐시 키에 넣는다. 프롬프트를 고치면 캐시가 자연히 갈린다.

## 3. 비용 — 원 단위로 다시 센다

실측 프롬프트 크기(씨앗 1, 로스터 12~18명): **13,184 ~ 23,880자, 평균 19,102자 ≈ 5,300토큰.** 전체 198명이면 약 104,000토큰.
소넷 5 단가 입력 $2/M · 출력 $10/M, $1 = 1,400원, 출력 300토큰 기준:

| 보유 인원 | 입력 토큰(추정) | 1건 비용 | 비고 |
|---|---|---|---|
| 15명 | 5,300 | **약 19원** | 얇은 로스터 = 폴백이 주로 열리는 구간 |
| 50명 | 17,000 | 약 52원 | |
| 100명 | 35,000 | 약 102원 | 이 구간은 실사용/아키타입 경로가 대개 열려 AI를 안 부른다 |
| 198명 | 104,000 | 약 295원 | 사실상 발생 안 함(폴백이 안 열린다) |

- **캐시가 없으면** 하루 1,000건 × 19~52원 = **1.9만~5.2만 원/일**. 지금 상한 `AI_DAILY_GLOBAL_LIMIT=1000회`는 설명(4.9원)에 맞춘 값이라 그대로 두면 안 된다.
- 상한을 **원 단위**로 바꾼다: `AI_DAILY_BUDGET_KRW`. 호출마다 `usage` 토큰으로 실제 원가를 계산해 `ai_daily_budget`에 **누적 원**으로 더한다(지금은 횟수). 초과 시 엔진 폴백 답을 내고 `budgetExhausted`를 표시(지금 구조 그대로).
- 프롬프트 캐시(1h TTL)는 **로스터가 건마다 달라 안 걸린다.** 규칙 블록만 캐시해도 300토큰이라 이득이 없다. 쓰지 않는다.
- Batch API는 실시간 응답이라 못 쓴다. 평가(§5)에만 쓴다(50% 할인).

## 4. 결정성·캐시

- `temperature: 0`. 그래도 같은 답을 보장하진 않는다 — 그래서 **응답 캐시가 결정성을 만든다.** 키 = `sha256({v:'v3', ids: 정렬된 보유 id, mode, boss, tower})`. lang은 키에서 **뺀다**(조합은 언어와 무관) — 대신 `reasoning`은 lang별로 따로 캐시(지금 `ai_explain_cache`가 하는 일).
- 유저 간 공유: 보유 로스터가 글자 그대로 같을 때만 적중한다. "부분집합이 같으면"은 안 한다 — 로스터 하나가 늘면 답이 바뀌는 게 정상이다.
- TTL: 데이터 갱신(주간 조사가 `usageTier`를 바꿀 때)마다 프롬프트 버전을 올려 무효화한다. 시간 TTL은 안 둔다.

## 5. 검증 — 검사에서 평가로

| 지금(엔진, 결정적) | 전환 후(AI 구간) |
|---|---|
| `verify` 19종이 매 변경마다 통과/실패 | **규칙 위반 0**은 그대로 검사(검산기가 런타임에 강제) |

| — | 프롬프트를 고칠 때마다 두 eval을 돌린다. API 키가 있으면 `--live`(수백 원), 없으면 서브에이전트 |

- 평가 정답지가 "클로드 판정"이라는 한계는 그대로다. 유저가 다르게 느낀 건이 생기면 정답지를 고치고 그 경위를 log에 적는다.

## 6. 롤아웃 — 셰도우 먼저

1. `AI_TEAMS_MODE=off|shadow|on` (기본 off).
2. **shadow**: 폴백 구간에서 AI를 부르되 **화면엔 엔진 답을 그대로** 내고, AI 답·검산 결과·비용을 `ai_team_shadow` 표에 적는다. 하루 2건이면 비용은 무시할 수준. 여기서 실제 방문자 로스터로 (a) 규칙 위반률 (b) 엔진과 다른 답의 비율 (c) 응답 시간을 잰다.
3. **on**: 폴백 구간을 AI 답으로 바꾼다. 화면에 "AI가 구성한 조합" 표시 + 엔진 답을 `alternative`로 같이 보낸다(지금 `alternative` 자리 재사용).
4. 되돌리기 = 환경변수 하나.

## 8. 🙋 유저 결정이 필요한 것

| 항목 | 선택지 | 내 추천 |
|---|---|---|
| **일일 예산(원)** | 예: 5,000 / 10,000 / 20,000원. 19원/건이면 각각 약 260 / 520 / 1,050건 | 지금 트래픽(하루 2건)에선 어느 값도 안 닿는다. **규모 기준**이면 10,000원 — 1,000건/일이 넘으면 다시 정한다 |
| **모델** | 소넷 5(19원) / 오푸스 5(입력 $5·출력 $25 → 약 50원) | **소넷**. 오푸스는 실험을 안 했고, 소넷이 이미 엔진을 넘었다. 오푸스 실험은 API 키가 생기면 12문항(수백 원)으로 |
| **적용 범위** | 폴백만(§1) / 전부 | **폴백만**. 이유는 §1 |

## 9. 이 설계로 하지 않는 것

- 게이지 속도 표를 지어 넣지 않는다(출처 없음).
- 시뮬레이터로 AI 답을 고르지 않는다(판정과 무관함이 실측됨).
- 실사용/아키타입 경로를 AI로 바꾸지 않는다(검증 불가).
- `verify`에 AI 호출을 넣지 않는다(비결정적 + 돈).
