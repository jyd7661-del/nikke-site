# 주간 데이터 조사 예약 작업

매주 월요일 10:04(KST) 실행되는 예약 작업 `nikke-site-data-research`가 니케 관련 1차 출처를
훑어 데이터 파일을 갱신하고 보고서를 남긴다. 이 프로젝트에서 **사람이 안 보는 사이에 파일을
고치는 유일한 경로**이므로 규칙이 엄격하다.

## A / B 규칙 — 이 작업의 전부

| 등급 | 정의 | 처리 |
|---|---|---|
| **A** | 1차 출처의 값을 **그대로 옮긴 것** (티어표 숫자, 출시일, 스킬 텍스트) | 파일에 **자동 반영** |
| **B** | 추론·해석이 한 단계라도 들어간 것 (영상 총평, 커뮤니티 체감, 역할 판정) | **제안서에만** 기록 |

- `totemRole` 신규 등록은 **언제나 B**다. 토템은 조합 후보 생성의 뿌리라 잘못 넣으면
  엉뚱한 조합이 조용히 추천된다.
- 신규 SSR의 **오버스펙 여부 판정도 B**다. 근거 규칙은 `docs/data.md`.
- `[제목 기반 추정]` 표기가 붙은 항목은 영상 자막에 접근하지 못해 **제목만 보고 판단한 것**이다.
  근거가 약하므로 그대로 믿지 말 것.

## 실행하는 검사

```bash
node scripts/findTotems.mjs   # 기준선: 1군 0명
node scripts/checkData.mjs    # 기준선: ERROR 0 / WARN 3
```

> ⚠️ **지시서의 기준선이 아직 `WARN 0`이라 매주 오탐이 난다.**
> `name_ja` 도입으로 생긴 `NAME_SUBSTRING` 경고 3건은 정상이다. `ERROR 0 / WARN 3`으로
> 갱신해야 한다. → `docs/open-items.md`

## 커밋하지 않는다

**예약 작업은 git 커밋·푸시를 하지 않는다.** 파일만 고치고, 사람이 diff를 보고 직접 커밋한다.
사람 없이 백그라운드로 돌기 때문이고, 그 실행 환경에는 자격증명도 없다.

※ 이건 **예약 작업에만** 해당한다. 일반 세션은 정상적으로 커밋·푸시한다.

### 왜 이렇게 됐는지 — 같은 실수를 반복하지 않기 위해

2026-08-15에 Cowork에서 **클라우드 routine**으로 옮겼다가 2026-08-18에 되돌렸다.
옮긴 이유(결과가 git에 남는다, PC가 꺼져 있어도 돈다)는 그럴듯했지만 **일 자체가 되는지를
확인하지 않았다.** 그 샌드박스는 허용목록 방식 egress 프록시라 외부 웹이 전면 차단돼 있었다.
스크래핑이 전부인 작업을 스크래핑이 안 되는 곳에 둔 것이다.

그래서 `scripts/probeSources.mjs`를 만들었다. **환경을 옮기기 전에 반드시 이걸 먼저 돌린다.**

| 환경 | 접근 가능 | 비고 |
|---|---|---|
| **이 PC** | **6/6** | 지금 여기서 돈다 |
| GitHub Actions | 4/6 | prydwen·나무위키가 403 — 데이터센터 IP 차단 |
| 클라우드 routine | 0/6 | 허용목록 프록시. `403 CONNECT`. 위키피디아도 막힘 |
| Cowork | 6/6 | 예전 방식. 결과가 로컬에만 남고 사람이 커밋해야 했다 |

클라우드 routine(`trig_01Nm1CCwyhe9Qkhd8vRftsUi`)은 **꺼 두었다.** 지우지는 않았다 —
나중에 egress 정책이 바뀌면 되살릴 수 있고, 껐다는 사실 자체가 기록이다.

### 무엇이 바뀌었나 — AI가 하던 일을 코드가 한다

옮기면서 구조도 바꿨다. 주간 조사의 상당 부분은 AI가 필요 없다:

| 하는 일 | 누가 | 언제 |
|---|---|---|
| 신규 캐릭터 / 티어 어긋남 / 자료 신선도 / 검사 6종 | **코드**(`weeklyCheck.mjs`) | 매주 자동 |
| 무엇을 반영할지 판단, 출처가 갈릴 때 결정 | 사람 + AI | 보고서가 알릴 때만 |

`weeklyCheck.mjs`는 **찾아내기만 하고 데이터를 고치지 않는다.** 결과는
`reports/YYYY-MM-DD-auto.md`로 남고, 다음 세션에서 `checkWeeklyReport`가 미처리로 띄운다.
커밋도 일부러 하지 않는다 — 사람이 diff를 보고 판단하는 것이 이 프로젝트 방식이다.

자동 반영을 하지 않는 이유는 2026-08-15 사례다. prydwen 하나만 보고 티어 8건을 고치려다
다른 출처를 대조하니 7건에서 prydwen이 아웃라이어였다. 단일 출처는 '확인할 거리'이지 정답이 아니다.
