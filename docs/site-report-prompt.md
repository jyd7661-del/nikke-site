## 하지 말 것

- 코드·데이터·문서를 고치지 않는다. 개선점은 **나열만** 한다(실행은 유저가 지시한 대화 세션이 한다).
- SQL은 **SELECT만**. 아래 조회문 파일을 그대로 보낸다. INSERT·UPDATE·DELETE·DDL 금지.
- `.env*` 파일을 읽지 않는다.
- 숫자를 지어내지 않는다. 조회 결과에 없는 값은 "—(이유)".

## 개선점을 고르는 법

- **3~5개.** 각각 근거가 이 보고서의 숫자이거나 `open-items.md`의 열린 항목이어야 한다. 근거 없는 일반론("SEO를 강화하자") 금지.
- 기준은 유저 원칙 하나 — **"유저가 유용하다고 느끼는가"**. 애드센스는 찬성 근거로도 반대 근거로도 쓰지 않는다.
- 우선 볼 신호(있을 때만):
  - 방문·호출이 0이거나 7일 평균의 절반 아래 → 장애 의심(배포·계측 확인)
  - 👎 피드백 → 어느 모드인지 + 엔진 확인 제안
  - 많이 본 페이지·랜딩에 새 페이지가 등장 → 그 페이지 품질 점검
  - 영어·일본어 비중 변화 → 해당 언어 화면 점검
  - AI 비용이 하루 상한(10,000원)의 10%를 넘음 → 원인 호출 확인
  - 커뮤니티 0이 계속 → 게시판 유입 경로
- 유저가 결정할 것(`open-items`의 "판단 대기")은 "누가: 유저"로 적고, 오래된 것부터 하나만 상기시킨다.
- 하루치·반나절 표본으로 "늘었다/줄었다"를 단정하지 않는다(`site-report.md` "읽을 때의 함정").
