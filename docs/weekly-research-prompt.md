## 0. 실행 환경과 한계 — 먼저 읽을 것

- 저장소 루트(현재 작업 폴더)는 `~/projects/nikke/nikke-site-git`. 코드는 `nikke-site/`. **먼저 `CLAUDE.md`와 `docs/open-items.md`를 읽는다**
- node·npm은 실행기가 PATH에 넣어 두었다. 그냥 `node …`로 부른다(허용된 Bash 명령 목록은 `weekly-research.sh`에 있다 — 목록 밖 명령은 거부된다)
- **사람이 없다.** 질문하지 말고, 판단이 필요한 것은 보고서에 적고 넘어간다
- 30분 전(10:00)에 코드 점검 `scripts/weeklyCheck.mjs`가 이미 돌아 `reports/YYYY-MM-DD-auto.md`를 남겼다.
  **기계적으로 찾을 수 있는 것(신규 캐릭터·prydwen 티어 어긋남·신선도)은 그 보고서가 이미 찾았다 — 다시 찾지 말고 그것을 출발점으로 쓴다**
- **git은 쓰지 않는다**(읽기 `git status`·`git diff`만 허용). 커밋은 다음 대화 세션이 보고서와 diff를 보고 한다
- 쓸 수 있는 도구: 파일 읽기·쓰기·편집, WebFetch·WebSearch, Bash의 `node`·`npm run verify`·`curl`

## 1. 할 일 — 순서대로

### 1-1. 이번 주 `-auto` 보고서의 후속 처리

- **"신규 캐릭터 … 티어 있음 → 추가 가능"** → `docs/new-character.md`를 **처음부터 끝까지** 따라 추가한다.
  필수 필드(`id/title/name_kr/name_ja/class/burst/element/weapon/releaseDate/tiers/skills[3]`)와 `characters.js`·`img`·`game8PageMap`까지.
  **하나라도 못 구하면 추가하지 말고** 무엇이 없어서 못 넣었는지 보고서에 적는다. 값을 지어내지 않는다
- **"prydwen 티어와 어긋나는 값"** → `data/tierSources.json`의 `rule`대로 대조한다(살아 있는 출처끼리, **백분위로**, 모드를 맞춰서, enikk는 보조).
  **`tiers`와 `tierJudgments.json`은 고치지 않는다** — 출처별 값과 백분위를 표로 만들고 "제안 판정: 유지/변경/보류 + 이유"만 보고서에 쓴다
- **신선도 경고** → 고칠 수 있는 출처면 갱신, enikk면 "사람 필요"로 적는다

### 1-2. 스킬 문구 공백 채우기 (A — 자동 반영)

```bash
node scripts/refreshSkillsKrFromNamu.mjs --write    # 나무위키 한국어
node scripts/refreshSkillsJaFromGame8.mjs --write   # game8 일본어
```

둘 다 **숫자 대조를 통과한 것만 저장**한다. 실패 목록은 정상 동작이다(`docs/new-character.md` 함정 3) — 억지로 넣지 않는다.
돌린 뒤 `git diff --stat`으로 **바뀐 캐릭터가 누구인지** 보고서에 적는다. 예상 밖의 캐릭터가 대량으로 바뀌었으면 그 사실을 1절 맨 위에 적는다.

### 1-3. 유튜버 4인 — **전부 B(제안서 전용)**

## 2. 자동 반영 규칙

| 상황 | 처리 |
|---|---|
| 1차 출처의 값을 **그대로 옮기는 것**이고 다투는 출처가 없음 (신규 캐릭터 필드, 스킬 문구, 출시일) | **자동 반영** |
| 해석·추론이 한 단계라도 들어감 (영상 평가, 커뮤니티 체감, 역할 판정, 티어 판정) | **보고서에만** |
| 출처끼리 갈림 · 출처 1곳뿐 | 보고서에 출처별 값을 표로, 반영 안 함 |

### 절대 자동 변경 금지 — 조용히 망가지는 필드

값이 틀려도 에러가 안 나고 추천만 어긋난다. **출처가 몇 곳이든 보고서에만.**

- 기존 캐릭터의 `burst`·`id`·`title`·`name_kr`·`name_ja`·`tiers` (신규 추가 때 처음 채우는 것은 예외)
- `totemRole` · 오버스펙 플래그 · `tierJudgments.json` · 기존 데이터 **삭제**
- `metaStats.json`(enikk 사람 수집분) · 검사 스크립트의 기준선 숫자 — 기준선이 안 맞으면 보고서에 적는다. 래칫을 올려서 통과시키지 않는다

## 3. 검사 — 반드시

```bash
cd nikke-site
npm run verify
node scripts/findTotems.mjs     # 기준선: 1군 0명
```

- 파일을 하나라도 고쳤는데 **`verify`가 실패하면, 네가 고친 것을 편집 도구로 원래대로 되돌린다**. 되돌리지 못했으면 보고서 제목에 `[검사 실패 — 되돌림 필요]`
- 되돌렸으면 제목에 `[검사 실패 — 반영 안 함]`
- `findTotems` 1군에 이름이 뜨면 보고서에 옮긴다(등록은 B)
- 신규 캐릭터를 넣었으면 `npx next build`도 돌린다. 실패하면 그 추가를 되돌린다
