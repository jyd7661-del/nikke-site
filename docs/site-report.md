# 사이트 현황 보고 — 양식 (2026-10-21)

유저 요청: *"사이트 현황보고도 양식을 어느정도 정해놓는게 좋겠네."* 그 전까지는 물을 때마다 다른 표·다른 기간으로 답해서
주끼리 비교가 안 됐고, 근거 없는 숫자가 한 번 섞였다(10-20 "이전 평균 46위"). 그래서 **기간·항목·순서를 고정**한다.

## 언제

- 유저가 현황을 물을 때, 그리고 `/weekly-review`를 끝낸 뒤 덧붙여서.
- 기간은 **항상 같은 두 창**: 이번 = 어제까지 7일, 지난 = 그 전 7일(UTC 날짜). 오늘은 하루가 안 끝나 넣지 않는다.

## 어떻게 모으나

1. **DB 6개 절** — `nikke-site/supabase/queries/site_report.sql`을 claude.ai Supabase 커넥터 `execute_sql`로 **통째로** 보낸다(1행 JSON).
   `scripts/trafficReport.mjs`는 `.env.local`에 service_role 키가 없어 로컬에서 안 돈다.
2. **구글** — Search Console 실적 28일(노출·클릭·평균 게재순위·상위 검색어 3). 저장 프로필 `~/.pw-profiles/nikke-google`, xvfb + headless=False.
   매주 할 필요는 없다 — `open-items.md`의 "구글 노출" 확인일에만. 안 봤으면 "이번엔 안 봄"이라고 쓴다.

## 양식

한 줄 요약(좋아졌나·나빠졌나·그대로인가) 다음에 아래 표를 **이 순서로** 낸다. 값이 없는 칸은 지우지 말고 "—(이유)".

| 항목 | 이번 7일 | 지난 7일 | 메모 |
|---|---|---|---|
| 방문자(하루 평균) | | | `visits.this_people / 7` |
| 페이지 로딩(하루 평균) | | | 로딩/방문자도 한 번 |
| 유입처 상위 3 | | | `sources` — 2026-10-21부터 쌓인다 |
| 국가 상위 3 | | | `countries` |
| 언어별 로딩 ko/en/ja | | | `lang_loads` |
| 추천 사용(AI 설명 호출 / IP 수) | | | 엔진 추천은 서버 기록이 없어 **하한선** |
| 가입(신규 / 누적 · 로그인) | | | `signups` — 운영자 제외. 닉네임은 게시판용이라 가입 수로 쓰지 않는다 |
| 👍/👎 | | | 있으면 모드까지 |
| AI 비용(원) | 주 · 이달 누계 | | 우리 DB 기준 — 청구서와 기간이 다르다 |
| 구글(28일) | 노출 · 클릭 · 평균순위 | | 안 봤으면 "이번엔 안 봄" |

그 아래:
- **많이 본 페이지 상위 5**와 **첫 페이지(랜딩) 상위 3** — 한 줄씩
- **판단 1~2줄** — 숫자가 무엇을 뜻하는지, 다음에 할 일이 바뀌는지
- **주의 한 줄(고정)** — "운영자 본인 방문이 섞여 있고 데이터로는 못 가른다"

## 읽을 때의 함정

- **하루치·사흘치 표본으로 추세를 말하지 않는다.** 2026-08-28 "도감은 21%뿐"이 이틀 만에 61%로 뒤집혔다. 그래서 7일 창이다.
- **Search Console 클릭과 방문자를 맞춰 읽지 않는다** — 기준일(UTC 경계)이 다르고 검색 밖 유입이 섞인다. 10-21: 구글 28일 클릭 2인데 방문자는 하루 8명대였다.
- **유입처 `direct`는 "모름"에 가깝다** — 즐겨찾기·주소 직접 입력 말고도 앱 안 브라우저(카톡·디스코드)와 referrer를 지우는 브라우저가 전부 여기로 온다.
- **유입처는 랜딩만 센다** — 방문자 수보다 작은 게 정상이다(같은 날 두 번 들어오면 랜딩 2, 방문자 1).
- 표에 없는 숫자를 만들지 않는다. 비교가 필요하면 조회를 하나 더 하고, 그 조회도 여기 조회문에 넣는다.
