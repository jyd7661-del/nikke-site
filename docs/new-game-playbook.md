| 테스트·영상으로 **파티 구조 공개** | §9 착수 질문 30개에 답을 채운다 → 게임 규칙 모듈 설계 | `games/<game>/rules.md` |

| D+1 ~ 2주 | 공략 티어(prydwen 등)가 나오면 연결 · 첫 판정 벤치 20건 | 티어 점수 · 벤치 |
| D+2주 ~ | 랭커 실사용 조합이 공개되면 수집 규칙 정하고 **실사용 층** 추가 · 랭커 복원 측정 | 실사용 일치 · 복원율 |

실사용 층은 데이터가 생기면 붙인다 — 없는 동안 지어내지 않는다(§1-2).

## 1. 원칙 — 니케에서 효과가 확인된 것

### 1-1. 판단 기준은 "유저가 유용하다고 느끼는가" 하나

- 외부 심사(애드센스)는 반대 논거로도 찬성 논거로도 쓰지 않는다. 검색 거절 데이터는 **진단**(어느 페이지가 비었나)으로만 쓴다
- 기능을 늘리기보다 **틀린 정보를 없애는 쪽**을 택한다
→ `CLAUDE.md` 목표 · 메모리 nikke-ship-improvements · log 10 "도감에 대신 쓸 니케"

### 1-2. 근거 없는 숫자를 만들지 않는다

- "가중치를 줘서 해결하자"는 니케에서 **전부 실측으로 기각**됐다(스킬 시너지 가중치·파트너 우선·낭비 70%·버퍼 0명 관문…)
- 대신 **사실을 문장으로 밝히고 판단은 사용자에게** — 경고 문장(PvP 4RL보다 느림, 투자 조건, 애장품 미보유)
- 관문(gate)은 쓸 수 있다: **새 숫자가 아니라 데이터에서 나오는 문턱**일 때(예: 등록 실사용 194건 중 단독 3버스트 0건 → "단독 3버스트는 뒤로")
→ `CLAUDE.md` 원칙 2 · log 09 보완 9 "지표가 올랐는데도 기각"

### 1-3. "조용한 누락"이 가장 위험하다 — 검사를 데이터와 같이 만든다

- 니케에서 실제로 에러 없이 틀렸던 것: 이름 필드가 위키 템플릿 잔재라 SS 니케가 **모든 추천에서 누락**, 5인 팀이 2~4인으로 잘림,
  토템 목록 누락으로 정답 조합이 **한 번도 안 나옴**, 훅 누락으로 화면 섹션이 통째로 안 그려짐, 엔진이 실사용 픽률을 **계산해 놓고 버림**
- 규칙: **새 데이터·새 기능 = 검사기 확장**, 그리고 **검사를 만들면 일부러 고장을 넣어(역테스트) 잡히는지 확인**
- 검사의 판정 단위 = 고장의 단위(파일 단위 검사가 컴포넌트 스코프 버그를 놓쳤다). 판정 규칙은 실측 분포를 보고 정한다
→ `CLAUDE.md` 원칙 3·4

### 1-4. 엔진 변경은 "이전 엔진 대비"로 판정한 뒤 채택

- 지표만 보고 채택했다가 퇴행한 기록이 있다(버퍼 0명 관문, D1 1판). **바뀐 답을 하나씩 나란히 놓고 나아짐/나빠짐을 판정**, 나아짐 > 나빠짐일 때만
- 모든 엔진 변경에 **비교용 스위치**(`globalThis.__<GAME>_<NAME>_OFF`)를 남겨 옛 동작을 재현할 수 있게
- 효과가 0인 변경은 넣지 않는다(10-06 약점 속성 가산 딜러 한정: 129건 바뀐 답 0 → 되돌림)
→ `scripts/probeEngineChange.mjs` · `/engine-change` 스킬

### 1-5. 원문(1차 출처)을 끝까지 읽는다

- 손 요약이 틀린 사례: 애장품 17명 중 다수(목단 −20초 누락, 츠바이 반대로 적음), 아르카나 "무작위 카드"(실제는 확정 발동) → 관문을 뚫어 SS를 빼고 D를 넣음
- 데이터에 해석(note)을 적을 땐 **사용자 언어 원문**(desc_kr)까지 읽고 쓴다. 웹 검색 요약도 원문 확인(10-10 "9월 핵심 업데이트" 요약은 사실이 아니었다)
→ 메모리 nikke-treasure-from-source · log 10 아르카나 쿨감 오독

### 1-6. 유저의 게임 지식이 가장 강한 검사기다

- 유저가 잡은 것: 크크마 로테이션, 프리카+민트, 오버스펙, 토템 역할, 목단 애장품 쿨감, 민트↔프리카·마스트↔앵커 짝…
- 그래서 **유저가 깊게 아는 게임**을 고른다. 지적은 대체로 맞으니 진지하게 검증하고, 정답 예시는 **검사로 박는다**(`testDexRelations` 유저 정답 짝)

## 2. 데이터 층

### 2-1. 등급과 출처 규칙

| 등급 | 뜻 | 처리 |
|---|---|---|
| **A** | 1차 출처에서 그대로 옮긴 값(공식 스킬 문구, 공략 사이트 티어, 랭커 기록 화면 값) | 자동 반영 가능 |
| **B** | 추론·해석(토템 역할, 쿨감 해석, 배치 규칙) | 제안만, 근거 문서화 |

- **API·자동 수집기를 쓰지 않는다**(robots가 `/api/`를 막는 출처는 화면에서 사람이 옮긴다). 헤드리스 브라우저로 **화면 값**을 옮기는 것은 니케에서 써 왔다
- 출처마다 **수집 규칙 문서**(무엇이 무엇의 비율인가, 무엇은 더하면 안 되는가 — 예: 레이드 parses는 서버별 표본, 타워 %는 풀 안의 비율)
- 사람이 옮긴 값은 **서로를 검증하는 두 열**로 검사(`% of clears ↔ totalUses/analyzedClears`), 이름은 DB와 글자 그대로 일치해야 ERROR 없음
- 표마다 **신선도(asOf · staleAfterDays)** — 만료된 표가 경고 없이 쓰이던 사고가 있었다
→ `docs/data.md` · log 09 "만료된 표 2개가 경고 없이"

### 2-2. 캐릭터 스키마(니케 기준, 새 게임은 §9로 조정)

`id`(URL 안전 — 공개 주소가 된다) · `title`(영문, 조인 키) · `name_kr`·`name_ja` · 역할 필드(클래스·버스트 등) · 속성 · 무기 · 출시일 · `tiers{모드}` · `skills[]{name,name_kr,name_ja,desc,desc_kr,desc_ja,cd}`
- **조인 키는 이름이 아니라 id**(이름 매칭은 표기 차이로 조용히 빠졌다 — `lib/rosterBridge.js` 머리 주석)
- 티어가 없으면 **넣지 않고 기다린다**(미평가를 지어내지 않는다)

### 2-3. 새 캐릭터 절차

- 자동 초안: `newCharacterDraft.mjs`(대조군·태그 역검증), 절차 `docs/new-character.md`(밟은 함정 5개), 주간 점검이 "신캐 N명, 티어 있음/없음"을 알려 준다
- 새 게임에선 **D-day에 전원을 한 번에** 넣으므로 이 절차를 배치로 돌릴 수 있게 만든다(§8-3)

## 3. 추천 엔진

### 3-1. 층위 — 이 순서가 효과적이었다

1. **랭커 실사용 조합 일치** — 로스터에 등록 5인이 다 있으면 그대로(근거 문장: 시즌·보스·기록 수)
2. **4/5 부분 일치** — 랭커 조합 4명 + 빈 자리를 같은 역할에서 채움. 랭커 복원 30.4 → 42.5% (지난 시즌 기록은 완전 일치에만 — 부분 일치에 쓰면 옛 메타로 끌려갔다)
3. **공략 추천 조합(아키타입)** — 빈 자리 있는 아키타입은 폴백과 같은 잣대로 겨룸
4. **보유 로스터 탐색(폴백)** — 순위 = 티어 합 + 실사용 채용률 등급 합. 동점 처리: 낭비 인원 → 빈 버프 → 스킬 시너지 → 버퍼 수 → **정렬 키**(입력 순서에 기대지 않기 — 같은 로스터인데 고른 순서로 답이 갈리던 사고)
→ `lib/synergyEngine.js` pickSiteTeam · log 10 "실사용 4/5 부분 일치"

### 3-2. 점수

- **티어 척도가 둘 이상이면 표를 따로 둔다**(prydwen SSS 9단계 vs enikk S 6단계 — 합치면 3등급 강등)
- 실사용 채용률은 **모드·시즌(보스 속성) 단위**로(전체 채용률을 쓰면 속성이 다른 보스에 엉뚱한 가산)
- 애장품처럼 **보유 여부가 성능을 바꾸는 요소**: 미보유면 실사용 가산·실사용 조합 둘 다 주지 않는다(유저: "완성된 조합을 쓰는 사람은 애장품이 있다고 봐야")
- 버퍼는 속성과 무관하게 쓰인다(약점 일치율 공격형 56% vs 지원형 B1 28%) — 속성 가산은 딜러 쪽 신호

### 3-3. 모드별로 다른 판 — 한 규칙을 전 모드에 걸지 않는다

- PvP·레이드에서 "낭비 인원" 판정을 껐다: 랭커 상위 PvP 팀의 59%를 0점 처리하고 있었다(+29 −2)
- 주기 관문(20초)은 캠페인·타워만(등록 조합 캠페인 0/20 · 타워 7/50만 느림), PvP는 속도 경고만(유저: "증명된 티어는 이유가 있다")
- 레이드는 **5팀 분배**(서로 다른 캐릭터로 여러 팀) — 한 팀 탐욕은 핵심을 몰아 가져간다. 등록 팀을 안 겹치게 먼저(set packing) → 등록 팀 1 → 8/25

### 3-4. 결정성·캐시

- 엔진은 **결정적**이어야 캐시와 검사가 성립한다(`testEngineDeterminism`). AI는 설명만(§5)

## 4. 측정 — 정확도를 "재는 법"이 가장 큰 자산이다

| 도구 | 무엇을 재나 | 니케 실적 |
|---|---|---|
| **판정 벤치**(`judgmentBench`) | 엔진 답 vs **내(클로드) 블라인드 판정** — 판정 근거를 적고, 갈리면 "엔진이 틀렸나 내가 틀렸나"부터 | 95% 목표 → 99.0% |
| **랭커 조합 복원**(`benchRankerRecall`) | 랭커 등록 5인 + 무작위 15명 로스터에서 그 5인을 되찾나 | 완전 42.7% · 4명+ 91% |
| ㄴ `--loo` | 자기 팀만 실사용 표에서 빼고(유출 방지) | |
| ㄴ `--holdout` | 엔진 데이터에 없는 **지난 시즌**으로만(진짜 일반화) | 17.6% |
| ㄴ `--drop-top` · `--no-treasure` | **초보형** 로스터(고티어부터 없음, 애장품 없음) | 88~100%(애장품 없는 랭커 팀) |
| **5팀 분배**(`benchRaidSquads`) | 정답 = 등록 팀 중 안 겹치는 5팀의 피해 합 최대 | `--loso` 8/25 |
| **탐침 스냅숏**(`probeEngineChange`) | 무작위·얇은 로스터 129건/모드의 답 — 변경 전후 비교·판정 | §1-4 |

교훈:
- **벤치 가정을 의심한다** — "레이드 초보형 73%"의 대부분은 엔진이 아니라 "애장품 전원 보유" 가정이었다
- **정답지를 바꿔 본다** — 내 판정이 기준일 때(95%)와 랭커 조합이 기준일 때(42%)는 다른 것을 잰다. 둘 다 둔다
- 실패 목록에는 **뺀 정답·버린 정답·넣은 캐릭터·로스터**를 남긴다(원인 분석이 쉬워진다)
→ `scripts/benchRankerRecall.mjs` · log 10 "초보형 로스터 오답 해부"

## 5. AI 활용 — 비용과 역할

- **AI는 확정된 조합을 설명하는 데만** 쓴다(엔진이 결정적이어야 하므로). 프롬프트·요청 본문은 **공용 파일**(`lib/aiExplainPrompt.js`)로 운영·실험이 같은 것을 쓴다
- 설명 모델: 하이쿠 5.5 + **effort medium**(건당 약 1.5원, 지시 준수 0/8 위반) — 생각을 끄면 길이·이름 지시를 덜 지켰다
- AI가 조합을 **짜게 하는** 실험: 스킬 원문만 주면 메타를 못 만든다(하이쿠 40% · 소넷 59%), 채용률 등급을 주면 소넷 73~80%지만 건당 67원.
  하이쿠 "엔진 후보 고르기"는 4.5·5.5 모두 엔진보다 못함(가까워짐 25 · 멀어짐 55) → **엔진 개선이 먼저**
- 운영 AI에는 **원 단위 일일 천장 + 횟수 천장 + 셰도우 모드**(기록만, 화면은 엔진 답). 셰도우를 켜자마자 "한 번도 안 돌던 코드"(구조화 출력 제약·temperature 거부)가 드러났다
- 모델을 바꿀 땐 **API 차이**(temperature 거부, 생각 기본값, 출력 상한을 생각이 먹음)를 먼저 확인 — 소넷 셰도우 42%가 답 없이 끝났다
→ `docs/ai.md` · log 10 하이쿠 5.5 · log 09 셰도우 12건 분석

## 6. 사이트·콘텐츠·검색

### 6-1. 도감 = 데이터가 곧 페이지

- 캐릭터 DB 하나로 상세 페이지를 **빌드 때 정적 생성**(유지비 0). 표시 값은 데이터 그대로, 새 판정 금지
- **얇은 페이지는 구글이 거절한다**: 색인된 도감 한글 중앙 1,738자 vs 거절 382자. 기본 정보+티어+공식 스킬문만으로는 다른 사이트와 같다
- 도감에 오는 사람의 질문으로 절을 만든다: **대신 쓸 니케**(같은 역할 상위 티어) · **함께 쓸 니케**(랭커 조합 동반 비율 + 추천 조합 수) · **스킬로 이어지는 니케**(조건부 버프 대상절)
- 클라이언트 컴포넌트에 데이터 파일을 import하지 않는다(번들 94 → 347kB 사고). 서버에서 풀어 **순수 데이터만** 넘긴다
→ log 10 "도감 점검" · `.claude/rules/ui-i18n.md`

### 6-2. 다국어

- 라벨(i18n 키)만 보지 말고 **데이터**(조합 이름·설명·스킬)가 사용자 언어로 나오는지 검사(`testDataI18n` — 한국어 화면에 영어 466건이 나가던 사고)
- 언어별 주소(`/en`·`/ja`) + hreflang. **검색봇에게 브라우저 언어 자동 선택을 하지 않는다**(구글봇 en-US에게 사이트 전체가 영어로 렌더링 → 한국어 검색 노출 붕괴)
- 이름은 공식 표기(용어집 `glossary.json`), 근거 문장의 이름은 AI 프롬프트용(영문)과 화면용(사용자 언어)을 구분
→ `docs/i18n.md` · log 09 "구글에게 사이트가 영어로"

### 6-3. 검색·도메인

- 새 도메인은 순위를 처음부터 쌓는다(니케: 08-24 전환 → 2~3주 노출 상승 → 09-13 급락, 기술 원인 없음). **게임 이름 확정 즉시 도메인·브랜드 결정**
- 출시 전에 **구글 Search Console + 네이버 서치어드바이저(소유 확인까지!)** — 니케는 네이버 등록이 안 돼 0페이지였다
- 렌더링 결과로 확인한다(curl이 아니라 리치 결과 테스트·URL 검사의 "크롤링된 페이지 보기"). Search Console은 저장된 구글 프로필로 키 없이 읽힌다
→ 메모리 nikke-env-facts · log 10 "검색 노출 회복 확인"

## 7. 운영 자동화

- **주간 점검**(코드만: 신캐·티어 어긋남·신선도·검사) + **주간 AI 조사**(무인 실행, 데이터는 고치되 커밋 안 함 → 다음 세션이 diff 보고 커밋)
- 멈춤 감지는 **실행기별로**(한 신호에 섞으면 5주 멈춘 것을 못 잡았다) · PC가 꺼져 있던 주를 **따라잡기**(주 1회만 시도)
- 검사 묶음 `npm run verify` 하나 — 통과하면 자동 커밋·푸시, 배포를 미룰 이유가 생기면 유저에게 묻는다
→ `docs/weekly-research.md`

## 8. 필요할 것 — 아직 없는 것

### 8-1. 엔진 분리(지금 할 수 있고 니케에도 도움)

| 공통 뼈대(`lib/core`) | 게임 규칙(`games/<game>`) |
|---|---|
| 후보 생성(역할 칸별 상위 N), 순위·동점 처리·정렬 키 | 팀 유효성(니케: 버스트 Ⅰ·Ⅱ·Ⅲ), 역할 단계, 유연 역할 |
| 실사용 일치(완전·부분·지난 시즌), 아키타입 일치, 폴백 경쟁 | 주기·쿨감, 토템, 장비(애장품), 낭비 판정 여부(모드별) |
| 티어·채용률 점수 틀, 관문 틀(데이터 문턱 + 스위치) | 속성·약점, 모드 정의(타워 풀, 레이드 5팀) |
| 근거 문장 조립 틀(언어별), 결정성 | 스킬 문구 해석기(대상절·버프 종류 — 게임마다 문법이 다름) |
| 측정 도구(벤치·복원·탐침)의 입력 어댑터 | 게임별 데이터 어댑터·수집 규칙 |

- 방법: 니케 동작을 **한 줄도 바꾸지 않는 리팩터**로, 각 단계마다 verify + 판정 벤치 99% + 랭커 복원 42.7% + 탐침 스냅숏 "바뀐 답 0"을 확인
- 팀 구조를 모르는 게임의 모듈은 **미리 짓지 않는다**(버리게 된다)

### 8-2. 출시 직후(티어·랭커 데이터 없음) 전용 모드

- 공략 티어가 없을 때의 점수: **역할 제약 + 스킬 문구 신호만**으로 "유효한 팀"을 내고, 화면에 "아직 공략 티어가 없어 역할 기준으로만 짰다"를 밝힌다
- 판정 벤치를 가장 먼저(20건) — 유저 게임 지식으로 정답을 만든다

### 8-3. 데이터 입수 도구

- 공식 문구 3개 언어 수집기(니케: 나무위키 공식 문구·game8·prydwen) → 새 게임 출처 조사 후 같은 틀
- 새 캐릭터 일괄 추가(D-day 전원), 스킬 문구 **숫자 3개 언어 교차 검증**(`testSkillSources` — game8이 두 캐릭터 스킬을 뒤바꿔 올린 것을 잡았다)
- 화면 값 수집 체크리스트(헤드리스 크롬 · 접근성 이름으로 아이콘 판독 · 정렬 검사)

### 8-4. 멀티게임 사이트 구조

- 도메인/라우팅(게임별 도메인 vs `/<game>/` 경로), 공용 컴포넌트(도감·결과 패널·5팀 분배), 게임별 용어집
- 측정 도구·주간 점검이 게임 인자를 받게(`--game=`)

## 9. 새 게임 착수 질문 — 공개되면 하나씩 채운다

**팀 구조**
1. 한 팀 인원은? 고정인가 모드마다 다른가?
2. 팀이 성립하려는 필수 조건은?(니케의 버스트 Ⅰ·Ⅱ·Ⅲ 같은 것)
3. 역할(클래스) 종류와, 한 캐릭터가 여러 역할을 맡을 수 있나?
4. 같은 캐릭터 중복·같은 캐릭터 다른 버전(코스튬) 동시 편성 가능?
5. 배치(자리)가 성능을 바꾸나?

**전투 리듬**
6. 궁극기·연계기의 쿨타임/게이지 구조는? 주기를 맞추는 것이 메타의 핵심인가?
7. 쿨감·게이지 충전을 주는 캐릭터가 있나?(니케: 쿨감이 20초 주기를 결정)
8. "쓰지 않아도 상시 효과로 기여하는 자리"(토템)가 있나?

**속성·상성**
9. 속성/약점 체계? 딜러만 맞추면 되나(니케) 전원이 맞춰야 하나?
10. 무기·공격 타입별 버프(관통·차지·폭발)?

**성장·장비**
11. 캐릭터 성능을 바꾸는 개별 장비(니케 애장품)가 있나? 보유 여부를 사용자가 표시해야 하나?
12. 돌파·성급이 평가를 크게 바꾸나?(니케: prydwen 특수 표시 — 투자 조건 경고)

**모드**
13. 엔드게임 모드 목록(레이드·타워·PvP·스토리) — 모드마다 팀 수(5팀 분배?)
14. 보스·시즌이 바뀌며 메타가 회전하나?(시즌별 실사용 표가 필요)
15. PvP가 있으면 선공·속도가 승패를 가르나?

**데이터 출처**
16. 공략 티어 출처(prydwen이 이 게임을 다루나? 갱신 주기?)
17. **랭커 실사용 조합이 공개되나?**(공식 랭킹 화면 · 커뮤니티 집계 사이트) — robots·이용 조건
18. 공식 스킬 문구 3개 언어를 어디서 얻나?
19. 캐릭터 이미지 출처·라이선스
20. 한국어 위키·커뮤니티(정답 예시·용어 표기)

**사이트**
21. 게임 공식 명칭(한·영·일) → 도메인
22. 출시 국가·일정(한국 동시 출시?)
23. 경쟁 사이트(game8·namu·prydwen·인벤)에 없는 것 = 우리 차별점("내 로스터로 짜기")
24. 첫날 도감에 넣을 정보(공식 문구·출시 캐릭터 수)

**사람**
25. 유저가 이 게임을 얼마나 깊게 하나(정답 판정·오류 발견의 핵심)
26. 니케와 동시 운영 시 주간 시간 배분

**엔진 측정**
27. 첫 판정 벤치 20건의 로스터를 어떻게 뽑나(출시 캐릭터 수에 맞춰)
28. 랭커 복원의 정답지가 생기는 시점
29. 초보형 로스터의 정의(무료 지급·상시 모집 캐릭터 — 니케의 상시 SR처럼)
30. 이 게임에서 "조용한 누락"이 날 만한 곳(이름 표기·코스튬·중복 id)

## 10. 함정 모음 — 니케에서 밟은 것(새 게임에서 같은 모양으로 온다)

| 함정 | 증상 | 막는 법 |
|---|---|---|
| 이름 매칭 | 표기 하나 달라 캐릭터가 조용히 빠짐 | id 조인 · 이름 대조 검사 |

| 계산해 놓고 버림 | 값이 있는데 순위에 안 들어감 | "이 신호가 실제로 순위를 바꾸나" 측정 |
| 지표만 보고 채택 | 퇴행 | 이전 엔진 대비 판정 |
| 벤치 가정 | 엔진 탓으로 오해 | 가정을 바꿔 다시 잼(애장품 없음) |
| 정답 유출 | 복원율 부풀림 | LOO · 시즌 단위 제외 · 지난 시즌 검증 |
| '모름'의 관대함 | 모름이 관문을 통과시킴(아르카나) | 모름을 쓰기 전에 원문으로 확정 가능한지 |
| 받는 쪽 무시 | 지원형에게 공격 버프 연결 | 엔진의 받는 쪽 기준 공유 |
| 봇 언어 자동 선택 | 검색 노출 붕괴 | 봇 제외 · 렌더링 결과 확인 |
| 클라이언트 데이터 import | 번들 4배 | 서버에서 풀어 넘기기 · First Load 확인 |
| 출력 상한·모델 차이 | AI가 답 없이 끝남 | 셰도우로 실호출 · 설정을 실험과 검사로 묶기 |

| 등록만 하고 확인 안 함 | 네이버 0페이지 | 소유 확인·사이트맵·수집 요청까지 |
