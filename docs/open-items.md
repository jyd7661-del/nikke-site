### 2·3단계 구현 (2026-08-08)

`lib/synergyEngine.js`에 `TOWER_CORPS` / `TOWER_LABEL` / `isTowerEligible()` /
`filterRosterByTower()`를 추가하고, 세 진입점(`recommendTeams`, `findExactTeamMatch`,

```

  null      → 일반 트라이브 타워 (제한 없음). 기존 동작 그대로
  pilgrim   → manufacturer === 'pilgrim' || overspec === true
  그 외      → manufacturer === tower   (오버스펙은 소속을 유지하므로 이걸로 이미 커버됨)
```

**"아키타입에 타워 구분이 없다"는 걸림돌은 사라졌습니다.** 아키타입마다 무슨 타워인지
판별하려 했는데, **자격을 캐릭터 쪽에서 판정하고 로스터 하나만 걸러 넣으면** 나머지가 전부
따라옵니다 — 아키타입 후보 조건이 "멤버 전원 보유"라 자격 없는 멤버가 낀 조합은 자동으로
빠지고, `flexSlots`도 걸러진 로스터에서만 채워집니다. 아키타입 데이터를 건드릴 필요가 없어

**anon 역할로 4가지 동작을 실제로 시험했습니다:**

| INSERT | 성공 | 피드백 기능 유지 ✅ |

| UPDATE | 반영 안 됨 | 차단 ✅ |

⚠️ **나중에 이 테이블을 읽는 기능을 만든다면** anon 키로는 안 읽힙니다. 정책이 없으면
